# Yggdrasil Code Intelligence + Understand Anything

Mimir has **two complementary graph systems**:

1. **Personal knowledge:** existing `/v1/memory/atlas` and local RAG graph. User-scoped memories, bots, tasks, decisions, conversations, artifacts, sources and evidence. These must remain user-isolated.
2. **Code understanding:** new `/v1/projects/knowledge-graph`. Mimir's local source graph (files, folders, symbols and static import dependencies) or a graph generated by the upstream **Understand Anything** skill.

The UI is **Project Map → Code intelligence**. It searches all indexed nodes, shows 1-hop relationships, displays an interactive graph and an evidence-oriented node inspector. Its default viewport draws at most 120 nodes; search to browse the rest without rendering thousands of elements simultaneously.

## Source / attribution

Upstream project: https://github.com/Egonex-AI/Understand-Anything

Upstream license: MIT. The upstream parser, model agents, frontend and installer are **not vendored** here. Mimir uses its output as an optional interoperability source. The native fallback scanner is independently implemented with Node standard-library APIs.

## Local quickstart

From the **Mimir source checkout** (not merely its packaged Windows EXE):

```bash
npm ci
npm run graph:build
npm run dev:daemon
# separate terminal:
npm run dev:renderer
```

`npm run graph:build` produces `.ua/mimir-code-graph.json` as a local artifact. The API uses a live scan if the official plugin graph is not present. The scanner is read-only with respect to source files; its explicit CLI writes only the generated JSON.

## Optional: enable official Understand Anything analysis

Inspect the upstream installer before executing it; do not execute arbitrary remote scripts without reviewing them. The official author documents these installation commands:

**OpenCode, Antigravity, Codex, other agents (macOS/Linux):**

```bash
git clone https://github.com/Egonex-AI/Understand-Anything.git
cd Understand-Anything
less install.sh
./install.sh opencode
```

**Windows PowerShell:** download and inspect the upstream `install.ps1` in a temporary directory, then run the reviewed file with `-Platform opencode` if that is supported by the current installer. See upstream documentation for exact platform arguments.

In OpenCode, open the **Mimir source repository**, invoke the installed `understand` skill on its root, and use full analysis when you need a fresh graph. The official skill writes `.ua/knowledge-graph.json`, or the legacy `.understand-anything/knowledge-graph.json`. Mimir detects either location on the next graph refresh and identifies its source as `understand-anything`.

The official analysis may call an LLM; its first pass can cost significant tokens. Use a local model or approved subscription, and do not submit confidential repositories to cloud providers without permission.

## Native graph schema and endpoints

`GET /v1/projects/knowledge-graph` returns:

```json
{
  "schemaVersion": "mimir.knowledge-graph.v1",
  "source": "mimir-static-scanner",
  "nodes": [{ "id": "file:daemon/coordinator.mjs", "type": "File", "path": "daemon/coordinator.mjs" }],
  "edges": [{ "from": "file:daemon/coordinator.mjs", "to": "file:daemon/store.mjs", "relation": "imports" }],
  "stats": { "files": 1, "nodes": 2, "edges": 1 }
}
```

This snippet is **schema illustration**, not a report of Mimir's actual graph counts.

`GET /v1/projects/knowledge-graph?q=memory` returns a filtered subgraph with one-hop neighbors and valid intra-subgraph edges.

`npm run graph:build` writes `.ua/mimir-code-graph.json` for local inspection and exports. This file and official graph directories are gitignored by default because graphs can expose project structure.

## Trust, scale, and limitations

- Static parser extracts folder containment, imports and declared classes/functions. It does **not** provide an exact dynamic call graph, runtime behavior, semantic code explanations or human-grade business domain mapping. The official plugin can enrich semantics, but its summaries remain unverified until checked against source.
- No outbound calls or shell execution occur during a graph API read. No credentials, private file contents or chat history are embedded into code graph nodes.
- File walker skips symlinks, files above 512 KiB, generated/build directories, binary assets, and environment secret files. These exclusions mean \"everything\" is not a literal guarantee of every byte on disk.
- The personal-memory atlas remains distinct and user-scoped; **do not** blend it into a global source-code graph, which would risk cross-user data leakage.
- For other repositories, run official Understand Anything in that repository. The current integrated Mimir endpoint indexes the Mimir source checkout only. Broader user-selected repository support should be separately designed with permission controls and path sandboxing.
- Avoid copying official `.ua/knowledge-graph.json` into a different project; the graphs refer to source paths and commits that may not match.
- Validate on real source checkout with `node --test tests/code-understanding.test.mjs`, `npm run graph:build`, and `npm run build`. CI workflow enforces these checks on the PR.

## Future improvements

The highest-value upgrades would be Tree-sitter-backed call resolution, component-to-runtime trace evidence, typed architecture/domain connections, graph diffs across commits, and authenticated per-workspace graph storage. Those are not implemented here.
